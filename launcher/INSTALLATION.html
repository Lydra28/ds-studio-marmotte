Préparer DS-Studio, sans terminal

Ce guide reste lisible même sans Node.js. DS-Studio ne demande ni Python, ni Rust, ni compte IA. Le lanceur ne modifie aucun réglage système.

1. Installer Node.js si nécessaire

  1. Ouvrez le site officiel Node.js. Choisissez une version LTS, 22.12 ou supérieure, pour votre système et votre processeur.
  2. Windows / macOS : téléchargez l’installateur officiel, ouvrez-le et conservez npm. Si l’ordinateur est géré par l’école ou demande des droits que vous n’avez pas, contactez l’enseignant ; le lanceur ne contourne pas ces droits.
  3. Linux : l’installation graphique dépend de la distribution. Si le gestionnaire de logiciels ne propose pas Node.js 22.12+, demandez une installation adaptée à l’enseignant. Autre possibilité sans privilège : téléchargez l’archive Linux officielle adaptée au processeur, décompressez-la avec le gestionnaire d’archives, puis placez le dossier complet node-v…-linux-… dans .local/opt de votre dossier personnel (afficher les fichiers cachés). Le lanceur cherche aussi à cet endroit. Ne téléchargez pas un exécutable d’une source inconnue.
  4. Double-cliquez de nouveau sur le lanceur. Si le système ne voit pas encore Node, reconnectez votre session puis réessayez.

2. Ouvrir le bon lanceur

  • Linux : DS-Studio.desktop. Propriétés → Permissions → Autoriser l’exécution, puis « Faire confiance » / « Lancer » si votre bureau le demande. Le script et le fichier .desktop doivent rester dans le dossier du projet. Certains bureaux n’autorisent pas les .desktop téléchargés ; consultez l’enseignant plutôt que de désactiver une protection.
  • macOS : DS-Studio.app, dans le dossier du projet. L’application est légère, non signée et non notariée : le système peut la refuser. Utilisez les options d’ouverture explicites de Finder / Réglages de confidentialité si elles sont autorisées par votre établissement ; ne désactivez jamais Gatekeeper. Ne déplacez pas uniquement le .app.
  • Windows : DS-Studio.vbs (icône script Windows). Ce petit lanceur n’affiche pas de console. Windows Script Host / VBScript peut être absent ou bloqué par votre établissement : demandez à l’enseignant une entrée approuvée. Ne réduisez pas les protections Windows. Le lancement terminal historique reste disponible.

3. Préparer l’atelier

Le panneau s’ouvre dans le navigateur. Cliquez sur Installer / compiler…, lisez puis confirmez. Cela exécute npm ci puis npm run build dans ce projet uniquement (les scripts npm des dépendances peuvent s’exécuter). Internet et un dossier accessible en écriture sont nécessaires. Aucune installation privilégiée automatique. Une erreur reste affichée avec son journal.

Ensuite : Démarrer DS-Studio, puis Ouvrir DS-Studio. Pour arrêter, revenez au panneau et cliquez Arrêter DS-Studio. Fermer le navigateur ne suffit pas. Un nouveau double-clic retrouve le panneau. Arrêter et quitter le lanceur ferme aussi son petit service local.

Dépannage sans perte de données

  • Port occupé : fermez l’application qui utilise ce port, puis réessayez. Aucun processus n’est tué automatiquement.
  • Verrou après crash : une instance morte est récupérée automatiquement. Un PID actif, un verrou mal formé ou une ancienne instance non identifiable est préservé. Arrêtez l’ancienne instance par son terminal / panneau, ou demandez à l’enseignant d’identifier le PID. Ne supprimez jamais state.json et ne tuez pas tous les processus Node.
  • Navigateur non ouvert : vérifiez votre navigateur par défaut. Si le panneau est ouvert, son lien « Ouvrir directement l’atelier » reste utilisable même si l’ouverture automatique est bloquée.
  • Projet déplacé : arrêtez DS-Studio et quittez le lanceur avant de déplacer tout le dossier. Reprenez le lanceur à son nouvel emplacement.

macOS et Windows : implémentation à valider sur une machine réelle. La présence de ces fichiers n’est pas une preuve de test sur ces OS.
